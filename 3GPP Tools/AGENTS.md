# AGENTS.md — 3GPP Tools Developer & AI Agent Guide

This document is the authoritative technical reference for human developers and AI coding agents working on the **3GPP Meeting Tools & Diagram Converter** repository. It outlines project architecture, subsystem responsibilities, coding conventions, threading and execution rules, and security boundaries.

---

## 1. Project Overview

**3GPP Tools** is a comprehensive Python/PyQt5 desktop engineering environment tailored for telecommunications engineers and 3GPP standards delegates. It integrates:
- **PlantUML & Office Integration:** Live PlantUML editing with debounced preview and conversion to native editable Microsoft Visio (`.vsdx`) and PowerPoint shapes.
- **Specification Search & Evolution:** SQLite FTS5 trigram substring search across 3GPP specification releases with "First Added" chronological tracking, cutoff date detection, and OpenXML parsing of multi-part documents.
- **Protocol Inspection & Evolution:** Message and Information Element (IE) diffing across releases for 5GS/EPS NAS (TS 24.501, TS 24.301), 5GS UE Policies (TS 24.526 URSP & ANDSP, TS 24.588 V2XP, TS 24.555 ProSeP, TS 24.514 RSLPP, TS 24.578 A2XP), NR/LTE RRC, NGAP, GTPv1-U, PDU Session UP (TS 38.415), and PFCP (TS 29.244).
- **Meeting & Work Item Management:** Offline synchronization of 3GPP meetings, TDocs, dynamic agendas, cross-WG topic dossiers with unified decisions (RAN text agreements + SA/CT pCRs/CRs), incremental LLM delta feeds, email discussion summarization, and company contribution audits.
- **Local AI Intelligence (Ollama):** Zero-cost, 100% offline, privacy-guaranteed AI integration for TDoc technical triage, call-flow sequence generation, email stance summarization, and an evidence-grounded 3GPP Research Assistant.

## 2. Environment & Execution

### Prerequisites
- **Operating System:** Windows (primary environment, using Win32 COM APIs and Windows shell hooks).
- **Python:** `>= 3.8` (typically executed with Python 3.10 to 3.14 64-bit; Python 3.14 user-space installation without administrator rights is recommended, see `README.md`).
- **Zero-Admin Architecture:** 100% user-space execution. No administrator rights or UAC elevation are required to install or run the application.
- **Java JRE / JDK:** 64-bit Java 11+ recommended (or legacy Java 8) for PlantUML JAR rendering. Portable JREs are supported via zero-admin configuration.
- **Microsoft Office (Optional but required for Visio/Word features):** Microsoft Visio and Word desktop installations for COM automation. PlantUML editing and specification tools function without Office installed.
- **Local Ollama Daemon (Optional for AI features):** Running locally at `http://127.0.0.1:11434`.

### Installation & Launching
Dependencies are managed via `requirements.txt`:
```powershell
pip install -r requirements.txt
```

#### Startup Dependency Validation (`src/core/utils/dependency_checker.py`)
To prevent cryptic `ModuleNotFoundError` crashes at launch, all entry points (`main_tools.py`, `cli_tools.py`, `mcp_server.py`) perform an instant (<2ms), zero-dependency startup check before evaluating heavy or third-party imports.
- **Missing Dependency Detection:** Fast module resolution via `importlib.util.find_spec` and version constraint verification against `requirements.txt`.
- **Actionable Reporting:** Prints a clean ASCII banner indicating the exact active Python interpreter (`sys.executable`), missing package names, and the exact copy-pasteable pip install command.
- **Clipboard & 1-Click Repair:** On Windows desktop launches, copies the repair command to the clipboard and presents an interactive `MessageBoxW` dialog offering 1-click automatic installation via pip.
- **Safe Headless/CLI Operation:** Headless environments (MCP stdio, CLI, CI) bypass modal dialogs and log clean diagnostic error messages to `sys.stderr` without corrupting stdout streams.

Launch the application:
```powershell
# Using the Windows batch launcher (auto-detects Python 3.14, 3.x, or system python):
.\src\Launch.cmd

# Or directly via Python with proper PYTHONPATH:
$env:PYTHONPATH = ".;.\src;$env:PYTHONPATH"
python -m main_tools
```

Fully externalized to JSON (`src/config/plantuml_presets.json`) with Git-ignored user customization support (`src/config/plantuml_presets_user.json`). Features standalone "UE" presets (`participant "UE" as UE`, `actor "UE" as UE`, `Dual UEs`, `UE Subcomponents`) and individual 3GPP Network Functions (gNB, AMF, SMF, UPF, UDM, AUSF, PCF, NRF, NSSF, NEF, UDR, AF, SEPP, eNB, MME, SGW, PGW, HSS), in-app `UserPresetDialog` for code-free preset creation/editing, and hot reload without application restarts.

- **Java Maintenance:** `JavaMaintenanceDialog` inspects Java runtime versions (Legacy vs Modern) and auto-updates PlantUML JARs.
- **AI Call Flow Generator:** Modeless dialog streaming sequence diagram synthesis from textual 3GPP procedure descriptions into the editor via chunked Ollama HTTP streaming. Features customizable 3GPP architectural style directives (box groupings, message IEs, state transitions, alt/opt branches, autonumbering), embedded procedural presets from TS 23.502/38.300, live in-dialog SVG diagram preview tab, automated background syntax validation with 1-click error auto-fix, and multi-turn conversational refinement.

- **Visio & Office Conversion Studio (`batch_convert_tab.py`, `src/modules/puml2visio/ui/cards/`):** Multi-card architecture organized into modular cards (`PumlBatchCard`, `OfficeBridgeCard`, `VsdxExtractorCard`, `StencilsCard`, `RecentExportsStrip`):

  - **Card 1: Batch PlantUML Converter:** Multi-format conversion (`.vsdx`, `.pptx`, `.svg`, `.txt`), options (source code embedding, auto-open), compact drop target with file/folder browse buttons, and staging queue with automatic diagram type detection (`Sequence`, `Class`, `Activity`, `State`, `Component`).
  - **Card 2: Office Format Bridge:** Lossless bidirectional PowerPoint (`.pptx`) ⇄ Visio (`.vsdx`) conversion via Enhanced Metafile (EMF) bridging and text shrink-wrapping.
  - **Card 3: Visio PlantUML Extractor & Reverse Engineering:** Instant headless OpenXML extraction (<5ms) of embedded PlantUML source code from `.vsdx` files with syntax-highlighted editor preview, clipboard copy, and 1-click **"📝 Open in PlantUML IDE Tab"** bidirectional routing.

  - (4) **Studio UI & Ergonomics:** Modern segmented direction pills (`📄 Word → Markdown` / `📝 Markdown → Word`), smart file drop routing with archetype badges (`.docx`, `.doc`, `.pptx`, `.ppt`, `.md`), automatic direction swapping, and output actions (`📂 Open Folder`, `👁️ Open in Word`, `📋 Copy Path`).
  - (5) **Meeting TDoc Exporters & AI Triage Integration:** Extended `DOC_EXTENSIONS` in `tdoc2md.py` and `tdoc_markdown_converter.py` to recognize `.pptx` and `.ppt` discussion papers inside meeting archives, allowing meeting synchronization, dossier export, and local Ollama AI triage to index and summarize presentation contributions alongside Word documents.
  - (6) **Empty & Incomplete PowerPoint Export Detection & Incremental Recovery (`export_manifest.py`, `tdoc_markdown_converter.py`, `post_meeting_exporter.py`, `pre_meeting_exporter.py`, `presentation_to_markdown.py`):** Ensures incremental briefings, dossier updates, and pre/post-meeting export sessions gracefully detect, repair, and persist previously incomplete, corrupted, or empty exports:
    - *Multi-Tier Completeness Guard (`is_export_complete`):* Validates file existence, non-zero size, minimal content threshold (rejecting stubs `< 120` bytes unless stamped by converter), unconditional fallback stub rejection (`"Document conversion was not available"`), corrupted prefix detection (`"__-________"`), slide presence (`"## Slide "` for presentation exports), and presence of all referenced slide screenshot images on disk.
    - *Incremental Manifest Planning (`plan_incremental_session`):* When extending existing meeting exports with additional TDocs, any existing empty, incomplete, or stub `.md` files are scheduled into `tdocs_to_update` rather than mistakenly skipped in `tdocs_to_skip`, guaranteeing re-conversion and slide figure generation.
    - *Manifest Reconstruction Protection (`reconstruct_manifest_from_directory` & `merge_manifest_into_tree`):* Prevents 0-byte or corrupted presentation stubs from being recognized as completed exports during directory reverse-engineering or tree merging.
    - *Manifest JSON Serialization Resilience (`_clean_for_json` & `_json_fallback` in `export_manifest.py`):* Recursively converts arbitrary Python nested types stored in meeting `row_data` (such as `set` objects like `_wi_tokens`, `tuple` objects, and `Path` instances) into sorted lists and strings, preventing `TypeError: Object of type set is not JSON serializable` crashes during manifest persistence.
    - *Collision-Free Slide Prefixing & Legacy Cleanup (`_clean_tdoc_prefix` in `presentation_to_markdown.py`):* Enforces clean single-pass regex sanitization (`re.sub(r'[^\w\-]', '_', ...)`), preventing character mangling regressions (which previously collapsed alphanumeric characters to `__-________`), and automatically purges old corrupted image artifacts from companion `media/` directories upon re-conversion.
    - *Robust Media Reference Resolution (`post_meeting_exporter.py`, `pre_meeting_exporter.py`):* In Phase 2 dossier writing, extracts all explicitly referenced image paths from `md_content` (`re.findall(r'!\[[^\]]*\]\(([^)]+)\)', md_content)`), searching across `local_media_dir`, `local_md_file.parent`, and companion `{stem}_media/` folders to guarantee all slide screenshots and diagram figures are copied into the destination `type_media_dir / img_name`.
    - *All-Engine TDoc Discovery (`_find_word_doc`):* Harmonized across `post_meeting_exporter.py`, `pre_meeting_exporter.py`, `dossier_exporter.py`, `llm_exporter.py`, and `tdoc_triage_worker.py` to locate `.docx`, `.docm`, `.pptx`, `.doc`, `.ppt`, and `.pdf` documents locally (prioritizing Word and PowerPoint over PDF) without redundant re-downloads or missing-document fallback stubs.
- **Document Sanitizer, Proofing Language & Revision Hub (F-07, `document_sanitizer.py`, `author_renamer.py`, `word_tabs.py`):** Pure Python OpenXML (`.docx` / `.docm`) ZIP package level engine providing unified pre-flight document sanitation for 3GPP delegates. Features: (1) **Proofing Language Unification:** Normalizes language across all document stories (body, tables, headers, footers, footnotes, endnotes, comments, and DrawingML canvas shapes) and styles (`styles.xml`, `docDefaults`), preventing newly typed text from reverting; (2) **Surgical Language Revision Purge:** Automatically detects and purges trivial Track Changes language formatting balloons (`<w:rPrChange>` tracking `<w:lang>`), while cleanly synchronizing compound revisions so text insertions/deletions and technical edits remain pristine; (3) **Revision Author Consolidation & Anonymizer:** Replaces disparate reviewer identities with a unified corporate signature (`'Deutsche Telekom'`, `'Editor'`, `'Rapporteur'`, `'Anonymous'`), synchronizes comment initials, and updates Dublin Core metadata (`dc:creator`, `cp:lastModifiedBy`); (4) **Executive Audit & KPI Dashboard:** Single-pass (<150ms) audit displaying detected language breakdown, language revision count, total insertions/deletions, and comment metrics; (5) **1-Click Presets:** Instant configuration presets for `3GPP Contribution Prep`, `Fix Language Only`, and `Full Anonymize`. ## 5. Architectural Rules & Constraints for AI Agents

When modifying or extending this codebase, adhere to the following architectural rules:

### 5.1. Threading & UI Responsiveness
- **Never block the Qt GUI thread:** Never execute network requests, database scraping, large document parsing, or LLM inference on the main thread.
- **Worker Conventions:** Use `QThread` subclasses or submit tasks to `QueueManager`.
- **Cooperative Cancellation:** Workers must periodically check `self.isInterruptionRequested()` or application `CancellationToken` instances. Never call `QThread.terminate()` as it can corrupt SQLite locks and C runtime states.
- **Safe Signal Delivery:** Pass data back to UI widgets via Qt signals (`pyqtSignal`) rather than directly manipulating widgets from background threads.

### 5.2. Win32 COM Automation Safety & Faulthandler Interaction
- **Apartment Initialization:** Any background thread using `win32com.client` must call `pythoncom.CoInitialize()` before accessing COM objects and `pythoncom.CoUninitialize()` in a `finally` block.
- **Resource Cleanup:** Always wrap Word/Visio COM operations in `try...finally` blocks to explicitly call `app.Quit()` and delete references (`del app`), preventing orphaned background `WINWORD.EXE` or `VISIO.EXE` processes.
- **Legacy Conversion:** Prefer direct `lxml` extraction for reading DOCX files; only invoke COM when native Word layout/rendering is strictly necessary.
- **Faulthandler & Windows Vectored Exception Handling (VEH) Pitfall:**
  - On Windows, `faulthandler.enable()` installs a Vectored Exception Handler (`AddVectoredExceptionHandler`). VEH intercepts *all* structured exceptions (SEH) across the entire process before application-level exception handlers (`__try / __except` or Python `try...except`) can run.
  - Out-of-process Windows COM servers (such as Microsoft Word, Excel, or PowerPoint) routinely raise structured exceptions when busy or rejecting incoming calls: specifically `0x80010001` (`RPC_E_CALL_REJECTED`: *"Call was rejected by callee"*), `0x8001010A` (`RPC_E_SERVERCALL_RETRYLATER`), or native C++ exception `0xE06D7363`.
  - Because `faulthandler` cannot determine whether an SEH exception will be handled downstream, it falsely classifies handled COM RPC rejections as fatal crashes, printing `Windows fatal exception: code 0x80010001` and full C/Python thread stack dumps to `stderr`.
  - **The Startup Watchdog Boundary:** `faulthandler.enable()` and `faulthandler.dump_traceback_later()` are strictly confined to the application startup window (to diagnose plugin registration and GUI initialization deadlocks). Immediately after `window.show()` succeeds and `cancel_dump_traceback_later()` is called in `main_tools.py`, `faulthandler.disable()` MUST be called on Windows (`os.name == 'nt'`). This ensures normal Python `try...except` blocks and `win32com` error handling receive and process COM rejections cleanly without false-positive fatal crash dumps.
- **Office Busy State & COM Error Handling:** Always wrap property accesses on live COM objects (such as `word.Documents.Count`, `word.ActiveDocument`, `doc.Name`, `doc.FullName`, `doc.Saved`) in safe `try...except` blocks. If Word is in a modal state (editing text, open dialog, menu active), return `None` or log at `DEBUG` level rather than allowing unhandled errors or spamming `INFO`/`WARNING` logs.
- **Word `SaveCopyAs` vs. Direct Disk Snapshotting:** Microsoft Word COM does not reliably support `Document.SaveCopyAs()` across all document states; attempting `SaveCopyAs` on dirty/unsaved, OneDrive/SharePoint-synced, protected, or macro-enabled documents throws OLE error `0x800a1704` (Word error 5892: *"This method or property is not available on that object"*). Functions creating snapshots (`document_opener.py`) must catch `SaveCopyAs` failures and fall back to copying the on-disk file directly using `shutil.copy2` (which succeeds because Word maintains shared read locks). For headless Word COM instances, fallback to `doc.SaveAs2(FileName=str(snap_path), AddToRecentFiles=False)`.
- **Background Active Word Status Polling Hygiene:** In `WordExtractorTab`, background polling (`_poll_active_word`) must **never** create disk snapshots (`allow_unsaved_snapshot=False`). Polling must be gated by tab visibility (`if not force and not self.isVisible(): return`) so COM queries are paused when delegates work in other tabs, with `showEvent` providing instant refresh upon tab activation.

### 5.3. Local AI & Corporate Proxy Bypassing
- **Strictly Offline & Local:** Do not add cloud LLM fallbacks. All inference must target the local Ollama instance (`127.0.0.1:11434`).
- **Loopback Proxy Bypass:** Use `core.network.session.get_ai_session()` for AI HTTP calls. This factory automatically detects RFC 1918 loopback addresses (`is_local_address()`) and configures `trust_env=False` to prevent corporate intercepting proxies (e.g., Zscaler, BlueCoat) from hijacking local inference traffic.
- **Prompt Decoupling:** Decouple prompt text into `src/config/prompts/` to allow live hot-reloading based on file `mtime` without application restarts.

### 5.4. Database Integrity & Multi-Store Isolation
The project intentionally separates domain data into distinct SQLite databases located in `src/db/`:
1. `3gpp_data.db`: Meeting schedules, TDocs, specification catalogue metadata, work items, and user tags/notes.
2. `3gpp_protocol_data.db`: Structured protocol models, messages, and IE hierarchies.
3. `3gpp_spec_search.db`: Extracted clause text with FTS5 trigram indexes.
4. `3gpp_spec_history.db`: Historical CR/p-CR ledgers and TDoc cross-references.
5. `user_tdocs.db`: User notes, personal review status, and triage archives.

- **Strict Database Preservation & Git Safe Handling (`src/db/3gpp_data.db`):**
  - **CRITICAL RESTRICTION FOR ALL AI AGENTS & SCRIPTS:** **NEVER execute `git checkout`, `git restore`, `git reset`, or `git clean` against `src/db/3gpp_data.db` (or any `.db` file in `src/db/`).**
  - **Root Cause & Impact:** `3gpp_data.db` contains live runtime data (newly synchronized specification releases, meeting TDocs, work items, and delegate annotations). Discarding local changes to `3gpp_data.db` via Git silently rolls the database back to an older commit snapshot, erasing newly added specification versions (such as TR 23.801-01 v0.10.0), downloaded meeting schedules, and user annotations.
  - **Skip-Worktree Protection:** `src/db/3gpp_data.db` has the Git `skip-worktree` bit configured (`git update-index --skip-worktree src/db/3gpp_data.db`). This ensures that local synchronizations and runtime SQLite writes are ignored by `git status` and protected from automated or accidental bulk working-tree resets (`git checkout .`, `git restore .`). Agents must never unset this flag or force-restore the database file.
  - **Schema Migrations:** If database schemas change, always write programmatic SQLite migration scripts (`ALTER TABLE`, column inspection, or table creation with backward compatibility) rather than replacing the live database with a blank template or older snapshot.
- **Cross-Database Queries:** Do not couple queries across these databases using SQLite `ATTACH` unless strictly isolated inside a dedicated maintenance script.
- **WAL Compaction & Storage Hub (`DatabaseMaintenanceDialog`):** Provides an executive storage dashboard featuring top KPI summary cards (Total Storage, Reclaimable Freelist Space, WAL Log Health, User Table Counts), two-tier table rows with domain-specific icons and filenames, and animated progress feedback for `PRAGMA wal_checkpoint(TRUNCATE)` and `VACUUM` batch compaction. Destructive wiping actions (`🗑️ Wipe`) are visually isolated with warning styles to prevent misclicks. Features 1-click **📂 Open DB Folder** in Windows File Explorer.

### 5.7. Protected Drop-In Files & External Components

### 5.8. Qt UI Text & Ampersand Mnemonic Escaping
- **Mnemonic-Aware Controls vs. Non-Mnemonic Widgets:**
  - **Mnemonic-Aware Controls (`QPushButton`, `QToolButton`, `QCommandLinkButton`, `QCheckBox`, `QRadioButton`, `QGroupBox`, `QAction`, `QMenu`, `QMenuBar`, `QTabBar`, and `QTabWidget`):**
    - In Qt/PyQt, these interactive controls interpret a single `&` as a keyboard accelerator mnemonic prefix.
    - Passing a single `&` (e.g. `"Save & Close"`, `"Work Items & Enrichment"`) causes Qt to swallow the ampersand and underline the following character on Windows (e.g. rendering `Work Items _Enrichment`).
    - **Literal Ampersands Must Be Escaped (`&&`):** For these controls, always write literal ampersands as `&&` in static code (e.g. `QPushButton("Save && Close")`, `QGroupBox("🎯 Work Items && Enrichment")`, `QAction("Tags && Notes")`, `QCheckBox("Followed && Starred")`).
    - **Dynamic Data Ingestion:** Strings loaded dynamically from external sources (`useful_links.json`, databases, FTP scrapes, network APIs) that contain `&` must be sanitized with `escape_qt_mnemonic(text)` from `core.ui.ui_components` before passing them to `menu.addAction()`, `btn.setText()`, `tab.addTab()`, etc. `escape_qt_mnemonic()` is idempotent.
  - **Non-Mnemonic Widgets & Text Surfaces (`QLabel`, `QLineEdit`, `QTextEdit`, `QTextBrowser`, `QToolTip`, `QStatusBar`, `setWindowTitle`, table/tree cells, and HTML markup):**
    - These controls and surfaces do **NOT** parse keyboard mnemonics (unless a buddy is explicitly assigned to a `QLabel`).
    - **CRITICAL RULE — Never Use `&&` Here:** If you write `&&` in a `QLabel` (e.g. `QLabel("Field && Structure Inspector")`), `label.setText()`, `setWindowTitle()`, `setToolTip()`, or HTML strings (`<b>...</b>`), Qt or the HTML engine will literally render `"&&"` on screen to the user!
    - In `QLabel`, window titles, tooltips, and placeholders, always write a single literal `&` (or `&amp;` in HTML).
- **Automated Regression Testing:** Both sides of this rule are enforced automatically by `tests/test_ui_ampersand_escaping.py`:
  - `test_no_unescaped_ui_ampersands_in_src`: Flags missing `&&` in mnemonic-aware controls.
  - `test_no_double_ampersands_in_non_mnemonic_widgets`: Flags improper `&&` in `QLabel`, window titles, tooltips, and non-mnemonic `setText()` calls.
  - Always verify compliance by running: `py -3.14 -m unittest tests/test_ui_ampersand_escaping.py`.

### 5.9. Documentation Synchronization & Mandatory Local Commit Workflow
- **Documentation as Code:** Never treat documentation as an afterthought. When adding new capabilities, refactoring architectural patterns, modifying configurations, or updating UI controls, update corresponding documentation (`README.md`, `AGENTS.md`, and module guides) in the same work unit.
- **Mandatory Autonomous Local Commits (No Waiting for Prompts):** The AI agent must **never wait for the user to prompt or remind them** to document or commit changes. As soon as an implementation, bugfix, or refactoring task is complete and verified:

  2. Run relevant tests / linters to ensure green status.
  3. Automatically stage changed files and create a clean, descriptive local git commit (e.g. `feat(...)`, `fix(...)`, `refactor(...)`, `docs(...)`).
  4. Only after completing documentation and local commit should the agent report completion back to the user.

This guarantees the user has full opportunity to inspect commit logs, review diffs, test changes, and amend commits before publishing upstream.

### 5.10. Dialog Modality, Floating Windows & High-DPI UI Rules
- **NEVER Use `Qt.WindowStaysOnTopHint` on Tool/Utility Dialogs:**
  - Forcing dialogs or floating windows to always stay on top pins them above *all* desktop applications (Microsoft Word, Teams, Outlook, web browsers). This severely impairs multitasking and delegate workflows.
  - Windows must be created with standard `self.setWindowFlags(Qt.Window)` without the `Qt.WindowStaysOnTopHint` flag.
- **Prevent Win32 Owner Window Pinning (super().__init__(None)):**
  - On Windows, passing a parent widget into `QDialog.__init__(parent)` causes Win32 to register the parent window HWND as `GW_OWNER`. The Windows Window Manager enforces that owned windows are *always* pinned above their owner in the Z-order, preventing delegates from bringing the main window in front of utility dialogs.
  - All modeless tool dialogs and windows (`SpecClauseExcerptDialog`, `CrPcrDialog`, `DatabaseMaintenanceDialog`, `DatabaseInspectorDialog`, `ProcessManagerDialog`, `TDocEmailsDialog`, `StandaloneEmailReaderWindow`, `EmailSummaryDialog`, `TDocTriageDialog`, `CallFlowDialog`, `SessionPlanWindow`, `SpecVersionHistoryDialog`, `SpecTDocReportDialog`, `SpecClauseDiffDialog`, `ContributionReportDialog`) must initialize with `super().__init__(None)` (storing `self._parent_ref = parent` and connecting `parent.destroyed.connect(self.close)` if parent is provided) so they can float and re-order freely behind or alongside the main application window.
  - Explicitly use `self.setWindowFlags(Qt.Window)` rather than `self.windowFlags() | Qt.Window`; because `Qt.Dialog = 0x3` and `Qt.Window = 0x1`, bitwise OR leaves the `Qt.Dialog` bitmask intact.
  - Spawning sites must retain a persistent reference to modeless dialogs (e.g. `self._active_cr_dialogs`, `self._active_excerpt_dialogs`, `self.db_maintenance_dialog`, `self._triage_dialogs`) to prevent premature Python garbage collection, and connect `dialog.destroyed` to discard.
  - Close event handlers (`closeEvent`) must guard worker thread inspections using `getattr(self, "_worker", None)` and cleanly request interruption with timeout wait/terminate (`requestInterruption()`, `wait(500)`, `terminate()`) to prevent Qt `QThread: Destroyed while thread is still running` fatal crashes.
- **Modeless Multi-Window Architecture (Qt.NonModal):**
  - Utility and inspector tools must be non-blocking floating windows (`self.setWindowModality(Qt.NonModal)`).
  - Launch with `.show()`, followed by `.raise_()` and `.activateWindow()`. Blocking modal dialogs prevent delegates from interacting with other tabs, searching specs, or cross-referencing documents.
  - Modal execution (`.exec_()`) is strictly restricted to brief confirmation prompts (e.g. `QMessageBox.question` before destructive actions) or simple modal input pickers.
- **High-DPI Scaling & Dynamic Button Sizing:**
  - Never set hardcoded tight pixel widths (e.g. `setFixedWidth(72)`) on buttons containing text and icons. Under Windows display scaling (125%, 150%, 200%) or custom system fonts, text will be clipped (e.g. `Inspect` -> `Insne`, `Compact` -> `Compa`, `Wipe` -> `Win`).
  - Rely on CSS padding (e.g. `padding: 2px 10px;`), `min-width` rules, and allocate generous container column bounds (`>= 280px` for multi-button table action cells).
- **Vertical Clearance & Font Descenders:**
  - Buttons and table row section heights must provide sufficient vertical clearance (e.g. button `min-height: 26-28px`, table row `defaultSectionSize: 46-48px`) so that character descenders (`p`, `g`, `y`, `q`, `j`) are never sliced off at the bottom border.

### 5.11. 3GPP Portal & TDoc URI Construction (`core.utils.portal_utils`)
- **Centralized URI Generation:** Always use `core.utils.portal_utils` (or its alias `core.utils.portal_urls`) as the single source of truth for constructing official 3GPP (3GU) Portal URLs (`https://portal.3gpp.org`). Never construct raw ad-hoc portal URL strings inside feature modules.
- **TDoc Contribution Parameter (`contributionUid`):** The 3GPP portal application (`/ngppapp/CreateTdoc.aspx?mode=view`) requires the query parameter `contributionUid` (e.g. `contributionUid=S2-2611250`). **Never use `tdocId`**, which is obsolete and rejected by the portal.
- **Base TDoc Extraction:** Use `extract_base_tdoc(tdoc_id)` or `get_portal_tdoc_url(tdoc_id, base_only=True)` to cleanly strip revision suffixes (e.g. `r01`, `rev2`) before querying the 3GPP contribution portal.
- **One-Click Launchers:** Prefer `open_portal_tdoc()`, `open_portal_meeting()`, `open_portal_create_tdoc()`, and `open_portal_work_item()` to cleanly launch official portal pages in the delegate's default browser with uniform logging.

### 5.12. Qt UI Label & Mnemonic Ampersand Escaping (`core.ui.ui_components.escape_qt_mnemonic`)
- **The Qt Mnemonic Collision Pitfall:** In PyQt5 / Qt on desktop platforms (Windows and Linux), a single ampersand (`&`) in string arguments passed to `QAction`, `menu.addAction(...)`, `QPushButton(...)`, `QCheckBox(...)`, `QRadioButton(...)`, `QGroupBox(...)`, `QTabWidget.addTab(...)`, `setTabText(...)`, or `addMenu(...)` is interpreted as a keyboard accelerator mnemonic prefix. Qt suppresses the ampersand and underlines the subsequent character (e.g. `"Check & Ingest"` renders as `"Check _Ingest"`).
- **Mandatory `&&` Escaping:** To display a literal ampersand in any Qt action, menu item, button, or checkable widget, developers and AI agents MUST escape it as a double ampersand (`&&`) or pass dynamic strings through `escape_qt_mnemonic()`:
  ```python
  from core.ui.ui_components import escape_qt_mnemonic

  # Mnemonic widgets (buttons, actions, menus, checkboxes, tabs): MUST use '&&'
  menu.addAction(f"🔄 Check && Ingest Latest Releases for TS {spec}...")
  btn = QPushButton("⚡ Updates && New Only")
  act = menu.addAction(escape_qt_mnemonic(f"Sync {group_a} & {group_b}"))
  ```
- **Strict Distinction for Non-Mnemonic Widgets:** Controls that do NOT parse mnemonics (`QLabel`, `setWindowTitle`, `setToolTip`, `setPlaceholderText`, line edits) will literally display double ampersands (`&&`) if passed. These must ALWAYS use a single `&` (or `&amp;` for HTML text):
  ```python
  # Non-mnemonic widgets (labels, window titles, tooltips): NEVER use '&&'
  lbl = QLabel("Drag & Drop file here")
  dlg.setWindowTitle("Edit Tags & Notes")
  btn.setToolTip("Select only releases that have updates & new versions")
  html_lbl.setText("<b>Venue &amp; Austrian Time</b>")
  ```
- **Mandatory Automated AST Regression Linter (`tests/test_ui_ampersand_escaping.py`):**
  - All changes touching UI widgets, menus, actions, or dialogs MUST be verified against `tests/test_ui_ampersand_escaping.py`.
  - The AST test suite continuously scans the entire `src/` codebase to assert zero single ampersands in mnemonic widgets AND zero double ampersands in non-mnemonic widgets.

When adding new features or fixing bugs:
1. **Verify Python Syntax & Imports:** Ensure imports resolve cleanly with `PYTHONPATH=".;src"`.
2. **Preserve Comments & Docstrings:** Do not strip existing architectural comments or docstrings from untouched code.
3. **Check Submodule Guides & Protected Files:** When touching protocol parsing, consult [`src/modules/nas/core/parsing/AGENTS.md`](file:///src/modules/nas/core/parsing/AGENTS.md). 5. **Manual Verification:** Because the application is a graphical Qt desktop environment, test modified tabs or workers by running `python -m main_tools` and verifying that the Qt event loop starts and stops cleanly without console tracebacks or thread leaks.
6. **Synchronize Documentation (Docs-as-Code):** Whenever introducing new features, configuration parameters, data models, or UI workflows, immediately update the relevant documentation:
   - Root [`AGENTS.md`](file:///AGENTS.md) (architecture overview, module guides, and safety constraints).

7. **Mandatory Autonomous Commit (Local Only, Never Wait for User Command):** Once a logical feature or bugfix is implemented, verified, and documented:
   - Run verification tests to confirm functionality.
   - Stage all modified and added files belonging to the work unit.
   - Create an atomic git commit grouping the implementation, relevant tests, and documentation updates together using conventional commit messages (e.g., `feat(module): ...`, `fix(module): ...`, `docs(agents): ...`).
   - Do **NOT** wait for the user to request a commit; executing documentation and local commit is an inherent and mandatory part of task completion.
